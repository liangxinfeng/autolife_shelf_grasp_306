# 姿态与动作

入口：抓取与任务流程 → 遥操动作编排器旁的「姿态与动作」。沿用本机深色界面和动作执行器，不启动另一套机器人控制器。

## 1. 调整姿态

- **关节**：选右臂、左臂、腰腿或头部，再选关节；也可在模型中点击「调关节」后点选关节。滑块、数值框及拖动模型只改变蓝色预览，点击「执行选中关节」才运动。
- **夹爪**：在左右臂关节列表里选择对应夹爪，使用345自身实测毫米标定（最大95毫米）。该换算不是夹紧力控制。
- **末端IK**：选左右手 → 取当前末端 → 以毫米移动X/Y/Z，或绕X/Y/Z旋转 → 可达后执行IK预览。机器人方向：X前、Y左、Z上；也可选择夹爪自身方向。只求解并执行所选手臂七轴，腰腿、头部、另一臂保持。模型TCP为名义几何位置，不代表重新完成实物夹爪标定。
- **身体高度**：输入0～40厘米的下降量，选择正向或反向，先预览再执行。0为直立目标，不是在当前位置再次下降。踝、膝、腰俯仰沿已有联动逻辑运动。
- 「姿态速度」用于本页单关节、IK、身体高度和执行保存姿态；不会改写原厂响应系数。动作串有独立的整体速度。

## 2. 保存与使用姿态

填写名称，选择保存「实机当前姿态」或「蓝色编辑预览」，再点击保存。保存的是全身23轴快照，包含夹爪。

选择已保存姿态后可预览、真机执行或删除；同名覆盖需要确认。单关节执行只下发指定组的目标，而执行已保存姿态会执行整份全身快照。

### 抓取页的全身复位

把实机调整到合适的准备姿态，点击「将当前姿态设为复位姿态」。这个按钮只保存**实机当前**的全部23轴，包括腰腿高度、腰部、头部、双臂和两侧各自的夹爪开度，不使用蓝色虚影。保存后立即生效。

抓取页「复位并准备」统一使用这个目标：保持当前位置使能，沿预检路径恢复全身，关节到位后再恢复夹爪。首次尚未设置时界面明确提示沿用原双臂/头部复位目标，不擅自把安装时姿态设为复位。不修改官方或VR自己的复位配置。

参考300原厂复位的双臂4秒、颈部2秒和腰腿15°/秒来组织路径；实际时间仍受移动距离、反馈跟随及碰撞检查影响，不能保证每次固定4秒。保留现有速度、加速度及反馈约束，避免重复渐进处理。已验证的低头贴身恢复仍先由操作者确认支撑，低速抬离后再正常复位。

## 3. 组合动作串

点击「加入动作串」或进入「② 编动作」，从姿态库添加多个姿态，通过上移、下移、移除调整顺序，填写动作串名称并保存。

- 整体速度控制动作节奏，不提供大量单帧参数。载入动作后100%表示保持该动作原来的节奏。
- 先模型预演，再在净空、有人看护条件下真机运行。模型预演是运动展示，不是环境障碍检测。
- 关节到位后执行夹爪变化；无夹爪变化、无停顿的相邻点沿现有平滑轨迹连续通过。
- 动作保存为姿态快照，因此后续修改/删除姿态库不会悄悄改掉已经保存的动作。
- 保存的动作与遥操编排器共用动作库，可以直接在原任务流程中选择。连续录制轨迹仍使用原遥操动作编排器编辑，不在本页转换或覆盖。
- 关闭窗口时保存未完成动作草稿，下次进入本页可选择恢复。多人/多窗口改写动作库时会提示重新载入，不覆盖别人刚保存的动作。

## 4. 控制权和停止

浏览、编辑和模型计算不自动使能。动作串由已有执行器取得独占位置会话，结束后退出；手动调节使用下面的页面内保持会话。执行或VR示教期间不能编辑或启动第二个动作。

手动调节采用持续保持会话：第一次点击执行时，由原厂保持接口一次性锁存当前位置并使能；在本页继续调节关节、夹爪、IK或身体高度时复用该会话，不重复逐组切换电机模式。点击停止、离开本页或关闭程序时退出会话，保持力不变。保持会话只维护心跳，不持续发送新姿态；原厂状态退出、关节反馈中断仍会停止。

「执行选中关节」「执行IK预览」「执行身体高度」「执行姿态」点击即执行，不再弹二次确认；滑块和模型拖动仍只编辑预览。完整动作串的真机运行保留整段动作确认。手动单关节仅传所选轴，未选轴由底层用接收时的最新反馈保持。手动关节到位容差为0.2°，避免1°左右的微调被默认到位容差吞掉；不改电机响应系数、动作串或复位容差。首次使能仍需要原厂完成保持准备，不能承诺机械结构完全无声。

本页的停止按钮调用整个抓取程序的停止入口，停止动作并保留夹持。危险时使用实体急停。

## 文件职责

| 文件 | 职责 |
|---|---|
| `pose_workspace.py` | 合并工作区、模型、姿态库与动作串操作、异步IK界面 |
| `pose_workspace_data.py` | 姿态文件原子保存、输入检查、动作串快照组合、指定关节命令构造 |
| `pose_workspace_motion.py` | 通过已有唯一ActionExecutor完成保持式使能、所选关节/IK/身体高度调节和停止 |
| `pose_manual_session.py` | 手动调节的原厂保持会话、状态反馈核对与空闲心跳；不另写电机控制器 |
| `pose_ik_worker.py` | 独立纯计算子进程，复用345现有Planner；没有运动发布者 |
| `pose_geometry.py` | 从300姿态示教抽取的URDF坐标计算，使用345自己的模型 |
| `app.py` | 新页面入口、基于页面对象的路由、退出清理 |
| `action_studio.py` | 原执行器新增手动调节任务分派；原动作执行逻辑保留 |
| `workspace_reset.py` | 全身复位目标存储、版本核对、路径及腰腿速度约束 |
| `worker.py` / `planning.py` / `prepare.py` | 每次请求读取同一复位目标，完整几何预检，保留低头恢复 |
| `execution.py` | 全身复位使用原位置SYNC和停止保持；到位后恢复两爪各自开度 |

数据保存在本抓取包 `data/fixed_actions/`：`manual_poses.json`为手动姿态库，`saved_joint_actions.yaml`为与遥操共用的动作库，`manual_workspace_draft.json`为未保存动作草稿。不导入300姿态数据，不复制300硬件标定。

`manual_reset_pose.json`是本抓取程序的全身复位目标。重新设置会使旧抓取准备记录失效，必须按新目标复位后再识别抓取。
