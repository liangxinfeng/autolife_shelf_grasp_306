# 原厂 IK 与整段抓取轨迹

适用：345「抓取与任务流程」的视觉自动抓取。新版后台重新打开程序后加载，不会因安装自动使能或运动。

## 动作链路

1. 同步图像、深度、关节与底盘状态，得到抓取目标。
2. 原厂 `autolife_robot_sdk.utils.kdl_ik_solver.KdlSolver` 解算选中手臂与腰部。首先使用限位 NR_JL；必要时使用同库 LMA 并独立复核限位、正解和目标误差。
3. 离线生成两段路径：预抓点连续进入实际抓点；闭爪后抬离、退出、连续收回。
4. 离线检查整条路径，并检查原厂最终线性插值经过的几何路径。按关节速度、加速度为路径分配时间。
5. 执行时调用原厂 `ArmTaskControlBase.move_joints_trajectory` 插值函数，通过既有位置 SYNC 通道输出。适配器不实例化第二个电机/CAN 控制器，也不改原厂服务。
6. 中间采样点不等反馈逐点推进。到实际抓点后确认到位再闭爪；收回结束确认到位并保持。

这里使用原厂求解与插值代码，项目仍负责物品几何、路径检查、时序准备和协议适配；不是把抓点直接交给一个不可检查的后台运动任务。

## 腰腿和收回语义

- 腰俯仰、腰旋转与所选手臂参与逆解；膝、踝保持规划开始时角度。
- 目标绑定识别时的固定底座坐标关系，不能随腰部转动而漂移。
- 收回使用当前工作区保存复位姿态的所选手臂七轴；腰部恢复抓取开始时角度，保持原来的下蹲状态。不会执行保存姿态中的站立腰腿目标。
- 另一臂和头部的关节角保持不变；腰动时它们仍会随躯干在空间移动，因此完整本体路径检查仍保留。
- 持物夹爪保持闭合。保存复位姿态发生变化后，旧抓取预览失效，需要重新规划，不能在执行时直接更换回程终点。

## 参数和文件

`config/grasp.yaml`：

- `grasp_backend: vendor_ik_trajectory`：选择新视觉抓取链路。
- `vendor_grasp_waist_range_deg: [12.0, 8.0]`：相对抓取初始腰角允许的俯仰、旋转范围，仍受模型及原厂限位约束。
- `vendor_grasp_arm_speed_deg_s: 60.0`：手臂轨迹速度上限，非电机响应系数。
- `vendor_grasp_waist_speed_deg_s: 20.0`：腰部轨迹速度上限。

`vendor_ik_process.py`：在原厂 Python 中隔离运行纯 FK/IK，避免与感知环境的运动学二进制库冲突。

`vendor_grasp_planning.py`：腰臂逆解、坐标锚定、抓取/持物路径与实际插值预检。

`vendor_grasp_trajectory.py`：离线定时、原厂整段插值适配、到点闭爪及结束确认。

`planning_control.py`：规划进度、取消与超时。取消停止纯计算子进程，不输出运动。

`arm_selection.py`、`planning.py`：只将视觉抓取调度到新后端，保留原有准备、放置、观察和录制动作链路。

`worker.py`：识别和规划期间校验底盘锚点；`execution.py`：沿用控制权、停止、心跳与夹爪状态，调用新执行器。

`pose_geometry.py`、`grasp_geometry.py`：合并另一聊天的夹爪工具轴修正。前进轴由安装面到指尖中心确定，夹持轴由两指位置确定；不沿用旧硬编码的错误轴方向。

## 验证与边界

- 真实依赖环境下，左右手 5 mm 纯 IK 位移及独立正解核验通过。
- 实际采集瓶子数据的右手完整抓取/收回计划通过；恢复保存手臂七轴、源腰腿及固定其他关节均被断言验证。
- 使用真正原厂插值函数和假接收端，计划两段运动共 4.76 秒，目标流实测约 4.89 秒；闭爪只发生在抓点到位后。该数字不代表真机抓取用时，不包含实际闭爪时间。
- 9 项新生命周期/时序测试通过。已有 139 项回归在旧安装和新候选均为 96 通过、43 失败，无新增失败；这些历史失败不能计作通过。
- 停止、失去控制权、通信异常、路径限位/碰撞及抓点末端到位检查仍保留。移除的是中途按反馈逐个推进的小目标机制。
- 尚未做新链路的真机抓取验收；需要现场净空、有人看护后先做单瓶测试。未修改原厂响应增益、速度配置或重启原厂服务。
