# 本轮任务耗时与优化

## 实际记录

任务顺序：入住区导航→抓纸巾→垃圾区导航→丢垃圾全程动作→返回入住区。

|环节|本轮记录|
|---|---:|
|入住区到点至抓取执行器启动|9.42秒|
|其中抓取规划|6.41秒|
|执行器准备至SYNC就绪|3.52秒|
|抓取前夹爪全开等待|5.50秒|
|垃圾区到点至动作实际开始|8.89秒|
|其中物体纠偏预览|4.72秒|
|其中控制准备阶段|约3.20秒|

这些不是单一固定延时，包含视觉、路径检查、进程初始化及真实夹爪运动。动作串本身约32.1秒，不计作衔接等待。本轮没有把首次使能或真正通信异常的检查取消，也没有改动原厂服务。

## 改动

1. `pose_geometry.py`预编译URDF拓扑，批量计算旋转，仍使用本帧所有关节值。
2. `pose_collision_scope.py`批量核对全连杆显示与碰撞模型变换，保留原有误差判据。
3. `vendor_grasp_planning.py`复用相同颈部角度的躯干到颈部相对FK；每次新路径重新绑定。不跳过变化后的颈部或新碰撞。
4. 相邻抓取路径区间只检查一次共享端点；最大0.5度采样间距不变。
5. `execution.py`与`grasp_gripper.py`在实测开口连续满足物品宽度加余量后停止张开并衔接抓取。`grasp_opening_margin_mm: 10`表示总余量10毫米。受阻、旧反馈及停止不能靠已发送目标冒充开口达标。闭合目标和原厂输出速度上限未改动。

## 对照验证

在同一机器人关闭应用后，用同一份记录执行纯计算：

|项目|旧版|新版|
|---|---:|---:|
|纠偏路径检查，三轮中位数|1.618秒|0.759秒|
|抓取热态规划，两轮均值|2.097秒|1.860秒|
|抓取首次规划|4.028秒|3.606秒|

模型路径1039个采样点及固定部件碰撞记录一致；最终抓取轨迹逐值一致，仅运行时间与去重后的检查计数不同。测试禁止ROS初始化；634项无动作测试通过。测试代码使用随包URDF，不依赖现场临时记录。

这些隔离耗时不能直接当作现场完整任务耗时；现场负载不同，实际记录的原规划为6.41秒。夹爪提前衔接已在有反馈模拟中验证，实机开口及整轮节省时间需现场复测。没有自动执行运动，没有改写用户姿态、地图、动作或物体记忆。
