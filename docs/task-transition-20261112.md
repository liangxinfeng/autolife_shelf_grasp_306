# 任务衔接与单次保持会话（2026-11-12）

## 解决的问题

此前抓取/放置先执行逐组保持使能，再进入原厂SYNC保持入口；两处重复准备。任务切换步骤也会释放刚建立的动作会话，导致后续重新接管。一次已有记录中，从执行器启动到SYNC就绪约4.47秒，这包含读取、加载及准备，不能全部归因于SYNC。

## 当前链路

1. 抓取/放置主动刷新硬件位置、核对规划起点、底盘状态和控制权。
2. 使用已读取的位置调用一次原厂保持式接管，待原厂反馈就绪后执行原有轨迹。
3. 调姿/动作串间及导航衔接保留本程序持有的会话、继续维护心跳；不借用其他程序的SYNC会话。
4. 转交独立抓取/放置进程、任务结束或停止时退出本会话。通信故障仍会停止，不跳过真正的硬件失效。

SYNC是当前原厂控制会话状态，并非电机速度模式。现有连续轨迹仍使用该入口，未改为ASYNC或速度控制。首次接管仍需使能；不能保证所有使能声音消失，也未加快电机参数。抓取与放置之间由于独立执行器边界，仍各有一次必要接管。

## 修改位置

- `pose_manual_session.py`：允许复用已完成的完整主动位置读取，进入一次保持会话。
- `execution.py`：原厂抓取/放置跳过重复的逐组使能；复位及旧执行后端保留原流程。
- `action_studio.py`、`teaching_studio.py`：任务调姿接入同一会话；保留腰腿补充使能和反馈确认。
- `task_flow_ui.py`：会话复用边界与任务结束清理。
- `test/test_transition_session.py`：无硬件输出测试，覆盖有效接管、坏数据、占用、拒绝、停止、导航调姿接动作和任务结束。
